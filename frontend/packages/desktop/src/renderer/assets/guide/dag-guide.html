DAG 工作流使用指南

把多个 Agent 编排成一条有先后顺序的自动化流水线，让它们像接力赛一样各司其职、协同完成复杂任务。

1什么是 DAG 工作流

DAG（有向无环图）工作流让你把任务拆成多个步骤（节点），每个步骤交给团队里的某个 Agent 执行， 并声明它依赖哪些前置步骤。系统会按依赖关系自动调度：只有当前置步骤完成后，后继步骤才会被触发。

① 调研 Agent→ ② 写作 Agent→ ③ 审校 Agent

上面的每一步都依赖上一步的产物（如文件、结论），因此必须按顺序执行——这正是 DAG 的用武之地。

2如何调用（3 步上手）

1 进入团队：在左侧打开一个至少有 2 名成员的团队（如包含 DDDcli 与 Claude Code 的团队）。
2 点击「Workflow」按钮：位于团队页右上角 Workflow 。点击后弹出流水线编排面板。
3 编排并运行：面板已按成员顺序生成默认流水线。你可以 ↑ ↓ 调整顺序、为每步填写专属指令、用 After ▾ 下拉框设置依赖关系，最后点 Run pipeline。

运行后可在团队运行状态中观察每个步骤的进度；每一步完成后，依赖它的后继步骤会自动开始。

3Agent 是如何配合的

团队里的 Agent 分两种角色，靠「信箱消息」与「依赖调度」两条机制协同：

LLead（协调者）

通常是 DDDcli。负责理解总目标、拆解任务、把子任务派给各成员，并在流水线中承上启下。它也能直接产出文件（如规格说明、总结）。

TTeammate（执行者）

如 Claude Code、Hermes 等。专注于被指派的具体步骤，读取前置产物、完成自己的那部分工作（写代码、做测试、翻译等）。

两条协同机制

  • 消息驱动：每个步骤会被写入对应 Agent 的「信箱」作为一条真实任务消息，Agent 像收到用户指令一样被唤醒并执行——所以它拿得到明确的步骤提示。
  • 依赖调度：调度器维护一张依赖图。某步骤的所有前置一旦完成，系统立即通知对应 Agent 认领并执行该步骤；未完成前则保持等待，绝不抢跑。

这意味着：你无需手动等待每一步，整条流水线会自行「前一步完成 → 唤醒下一步」地跑下去，直到全部结束。

4三个实战案例

案例 A研究报告流水线

调研 Agent：搜集资料 + 写 spec.md→ 写作 Agent：据 spec 撰写 report.md→ 审校 Agent：通读并产出 README

适合把「找资料 → 写正文 → 做摘要」这类内容生产拆给不同专长的 Agent，质量与速度兼得。

案例 B代码从零到文档

DDDcli：写需求规格 spec.md→ Claude Code：实现 calc.py→ DDDcli：据代码写 README.md

让执行型 Agent 专注写代码，协调者负责澄清需求与补文档，避免上下文混乱。

案例 C并行 + 汇聚（菱形）

翻译官 A：译英文→中文↘ 原文↗ 翻译官 B：译英文→日文→ 审校：对照两版产出对照表

两个翻译步骤可并行进行，都完成后才触发审校——DAG 的「汇聚屏障」会等齐所有分支再继续。

5小贴士

  • 步骤提示留空时，Agent 会沿用该成员在团队中的默认职责。
  • 「After」只可选排在前面的步骤为依赖，避免成环（系统会拒绝有环的定义）。
  • 每一步的产物（文件/结论）会留在团队工作区，后继步骤可直接读取。
  • 想随时查看进度，关闭本指南回到团队页即可，流水线在后台继续执行。
