### #14 对话消耗可视化（token 耗时 + 上下文占用）
- **目标**：每条 assistant 消息气泡下方显示运行耗时、token 双向消耗、上下文占用，让用户感知每次调用的真实成本。
- **已核查前提（2026-08-16 代码核实）**：
  - `session_events` 表（migration 042）**已有 `token_usage_json` 列**，且 `routes.rs:406/534` 的轨迹 API 已把它作为 `token_usage` 返回前端；rupoo `gateway.rs:540` 已把上游 `usage.input_tokens/output_tokens` 写入 `TokenUsage{prompt_tokens, completion_tokens}`。**→ token/耗时数据前端已可读取，无需新增 schema。**
  - **但** `token_usage_json` 目前常写 `{"duration_ms":...}` 或 `{}`——真实 `prompt/completion_tokens` 是否有值**取决于上游 API 是否回传 usage**（动手第一步须建真实对话查 DB 确认）。
  - rupoo `context.rs` 有 `estimated_context_tokens()` + `budget.total`（默认 4096），能算"上下文占预算比例"，但**该值未通过任何事件/API 暴露给前端**——要让 hover 显示真实占用，须后端在 `token_usage_json` 里补 `context_tokens`/`context_budget`（JSON 列内追加，不需新表/新 migration）。
- **显示形态（每条 assistant 消息下方一行 meta，11px `var(--text-quaternary)`，无边框无底色，与气泡间隔 4px）**：
  ```
  ⏱ 12.4s   ↑1.2k ↓3.8k   [IconStorage]
                                   ↑ hover：上下文 2,310 / 4,096 tokens (56%)
  ```
  - **图标用 Arco 组件，禁用 emoji**：上下文状态用 `IconStorage`（容量感）；接近预算上限（>80%）时切 `IconExclamationCircle` 并转警示色。**绝不用 📊 这类 emoji**（跨平台渲染不一致、风格廉价，与 Arco 精致感冲突）。
  - **末尾无模型名**（用户明确要求）。
  - hover tip 用 Arco `Tooltip` 组件（已被全局 `arco-override.css` 接管样式），显示真实上下文 token 数 + 占预算百分比。
- **诚实降级**：
  - 上游未回传 token → 只显示 `⏱ 12.4s   [IconStorage]`，不编造 `↑↓` 数字。
  - 上下文接口暂未做 → `IconStorage` 先不显示，等后端补完再上；**绝不显示假数据**。
- **聚合**：一轮含多步工具调用时，耗时取首尾差、token 累加，只显示一行。
- **不碰红线**：✅ 纯前端展示 + `token_usage_json` 写入层追加字段，不改 rupoo crate 名/标识。
- **验收**：真实对话后每条 assistant 消息显示耗时/占用；hover `IconStorage` 显示真实上下文比例；上游无 usage 时不显示假 token。

#### #14 后端落地（2026-08-16 已实现 ✅）
- **根因**：圆环一直不显示，是因为 `AgentTask::get_usage` 的 `Session`/`Rupoo`/`Aionrs` 分支全返 `Ok(None)`——`GET /api/conversations/{id}/usage` 拿到 null，前端 `ConversationContext.tokenUsage` 为空。
- **实现**：
  - **Rupoo/aionrs 路径（默认内核）**：`RupooAgentManager::get_usage()` 直接读 `self.agent.context().estimated_context_tokens()` + `ctx.budget.total`（同步、零 wire 往返），返回 `(used, size)`。`agent_task.rs` 的 `Self::Rupoo(m)` 分支序列化 `{used, size}`。
  - **claude/codex 路径（SessionAgentTask）**：后端 `capabilities().supported_commands.query_session_info` 为真时，发 `Command::QuerySessionInfo{ContextUsage}`，订阅 `backend.events()` 广播流等待下一个 `SessionEvent::SessionInfo{context_usage:Some}`；用 `tokio::time::timeout(5s)` 兜底防挂死；未广告能力或超时则返 `Ok(None)`。
  - 返回 JSON 经 `normalize_keys_to_snake_case` 落为 `used`/`size`，前端 `useAcpMessage`/`useAionrsMessage` 已映射 `tokenUsage.total_tokens=data.used`、`context_limit=usage.size`。
- **保留**：`Aionrs(AionrsAgentManager, aion_agent 内核)` 分支仍返 `Ok(None)`（旧路径，非默认内核）；前端两条路径均已接 `/usage`。
- **验证**：`cargo check -p roseui-ai-agent` 下我改动的 3 个文件 0 lint；其余为工作树既有 WIP 编译错误（factory AionrsResolvedConfig 字段），与本次无关。
