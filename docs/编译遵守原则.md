## 零、最终产品定位

**AionUi 本地 Agent 平台**：单个 Rust 二进制，本地运行，浏览器访问，面向小白与程序员的一体化工作台。

能力域：多 Agent 编排调度 · 办公文档处理 · 代码开发 · 项目分析 · 资料分析 · Wiki 知识积累。

数据全部留在本机，不依赖任何云端服务（模型 API 除外，由用户自备 Key）。

## 前置全局约束（不可修改、不可私自更换技术栈）

### 1. 项目现状

已本地完整克隆 `iOfficeAI/AionUi`(v2.1.44) + 依赖仓库 `AionCore`(v0.1.55)。

AionCore 后端已 100% Rust 实现，基于 Axum 0.8 + Tokio + SQLx 构建完整 AI 业务后端（24 个 crate 工作区），所有 API、WebSocket 流式对话、MCP/ACP 调度、文件系统、SQLite 存储逻辑均已生产可用。

### 2. 最终交付目标

彻底移除 Electron、Node.js 桌面外壳整套代码。

**不开发任何 Tauri 桌面客户端，不打包 exe/dmg/AppImage 桌面安装程序。**

最终形态 = **单个 Rust 二进制（内嵌前端静态资源）**，启动后浏览器访问即可完整使用全部功能。

#### 2.1 "纯 Rust 项目"的准确定义（验收口径）

| 维度 | 要求 |
|---|---|
| **分发物** | 100% Rust —— 单个可执行文件，零外部依赖目录 |
| **运行期** | 100% Rust 为主 —— 默认无 Node.js 进程；**唯一例外**：为支持 JS/npx 类 MCP 工具，`roseui-runtime` 可托管一处受管 Node 侧车，仅用于 MCP 协议调度，不得进入任何文档解析或业务路径（见 §模块 2.3） |
| **源码期** | 前端保留 TS/React；Node 仅作**构建期工具链**存在，不进入分发物 |

任何**非 MCP 用途**的 Node 运行时依赖均判定不合格；MCP 用途的受管 Node 须由 `roseui-runtime` 统一下载、缓存、校验，不得内嵌进二进制，不得触碰文档解析。

### 3. 锁定技术栈

**Rust 后端**
- Tokio 异步运行时
- Axum 0.8（网络底座）
- **SQLx 0.8 + rusqlite（维持现状，禁止更换 ORM）**
- tower-http 中间件套件
- Rust **edition 2024**，toolchain **1.95.0**（与 `rust-toolchain.toml` 一致）

**前端**
- 完整保留 React 19 + TS + UnoCSS + Arco Design SPA
- 不使用 Leptos / Dioxus 等 Rust 前端框架重写界面
- 包管理器 **bun**（与仓库现状一致）

**通信**
- RESTful HTTP + WebSocket 长连接（AI 流式输出）

**禁止引入**
- Topcoat、Tauri、Leptos、Dioxus、任何 SSR 全栈框架
- 任何替换 SQLx 的 ORM（含 Toasty、SeaORM、Diesel）
- SSE 等第二套流式协议

### 4. 代码硬性规范

**① Rust**
- edition 2024、rustfmt 格式化、clippy 零告警
- 杜绝 unwrap/expect 裸崩溃，统一 Result 错误处理
- 纯 async/await，无阻塞线程逻辑
- 按业务域划分 `router / handler / service / db / ws / utils`
- 手写工程师写实代码；拒绝冗余抽象、屎山分层、模板化样板

**② TypeScript**
- 严格类型校验，禁止全局 any 滥用
- 收敛环境差异代码，架构整洁可迭代

**③ 功能完整性**
所有改动必须兼容 AionCore 核心业务逻辑：Agent 调度、MCP 协议、文档解析、本地文件知识库、多模型对话、定时任务、Team 多 Agent 协作全部完整保留，不得删减。

### 5. 安全底线（本地 Agent 平台专属，不可妥协）

本平台具备**执行 shell 命令**（`roseui-shell`）与**读写本地磁盘**（`roseui-file`）能力，等同于把一个本地代码执行接口暴露在 HTTP 端口上。以下为强制要求：

1. 服务默认仅绑定 `127.0.0.1`；`--host 0.0.0.0` 必须显式指定，且强制要求已设置登录密码；
2. CORS **禁止**使用 `Allow-Origin: *` 或任意 origin 反射；
   - 生产模式：前端与后端同源，**不启用 CORS**；
   - 开发模式：白名单精确匹配 `http://localhost:5173`，仅在 `--dev` 下生效；
3. 保留 AionCore 现有 JWT + CSRF 双提交 Cookie 机制，**不得以"方便跨域"为由关闭**；
4. 校验 `Host` 请求头，拒绝非预期域名，防御 DNS Rebinding；
5. WebSocket 握手同样执行 Origin 校验；
6. 用户数据不出本机，无任何默认外发遥测。

## 一、整体改造核心思路

不推倒重写 AionCore，仅做网络层 / 适配层 / 分发层改造。

**原有拓扑**
```
Electron 主进程(Node) ── spawn ──> rosecore 二进制
       │                              ↑
       └── 托管 React 前端 ── IPC/HTTP ┘
```

**改造后拓扑**
```
┌──────────────────────────────────────────────────┐
│         rosecore  (单一 Rust 二进制)              │
│                                                  │
│  ┌────────────────────────────────────────────┐  │
│  │ roseui-webhost (新增)                       │  │
│  │  · rust-embed 内嵌 React dist               │  │
│  │  · Axum Router 装配                         │  │
│  │  · CORS / Host 校验 / 静态资源回退           │  │
│  └────────────────────────────────────────────┘  │
│                      │                           │
│  ┌───────────────────┴────────────────────────┐  │
│  │ 既有 24 crates（业务逻辑零改动）             │  │
│  │  conversation · ai-agent · mcp · team       │  │
│  │  cron · file · office · system · extension  │  │
│  │  channel · shell · assistant · project      │  │
│  │  + roseui-wiki (新增)                       │  │
│  ├─────────────────────────────────────────────┤  │
│  │ auth (JWT+CSRF) · realtime (WS/EventBus)    │  │
│  ├─────────────────────────────────────────────┤  │
│  │ common · api-types · db(SQLx) · assets      │  │
│  │ runtime                                     │  │
│  └─────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
            ↑ 127.0.0.1:3080 (同源)
            │  REST /api/*   ·   WebSocket /ws
    ┌───────┴────────┐
    │  浏览器         │  React 19 SPA（构建期产物，已内嵌）
    └────────────────┘
```

**四条落地路径**
1. AionCore 作为独立 Web 服务进程启动，内置 Axum，内嵌并托管前端静态资源；
2. React 前端打包为静态产物，构建期嵌入二进制，运行期同源访问，无跨域；
3. 原 Electron 承接的端口探测、进程生命周期、静态服务、系统路径、日志收集、数据库迁移全部下沉 Rust；
4. 前端消除全部 Electron 全局变量与 IPC 依赖，适配纯浏览器环境。

2. 建立统一宿主适配层 `renderer/services/HostBridge.ts`，标准接口：
   `getBackendPort` · `getInitialLang` · `collectLogs` · `captureScreenshot` · `recoverDatabase` · `on/emit` 事件订阅派发；
   **仅实现浏览器 Web 一套**。Electron 兼容实现不进主干（对比测试通过改造前的 git tag 进行）；
3. 瘦身 `common/adapter/ipcBridge.ts`（现 2,073 行）：删除废弃 IPC 通道，残留外壳能力全部转发至 HostBridge；
   `httpBridge.ts` 保留为请求核心，基地址改为可配置（同源时为空字符串）；
4. `vite.config.ts`：`base` 设为 `"./"`，产物适配内嵌托管；开发环境配置 proxy 指向 `:3080`，**保证开发态同源，规避跨域与 Cookie 问题**；

6. ESLint 增加规则：禁止 `renderer/**` 直接访问 Electron 全局对象，防止回退。

### 模块 2：公共共享层下沉（`packages/desktop/src/common`）

1. `common/types`（1,708 行）废弃手写类型，改由 AionCore `roseui-api-types` 经 **ts-rs / specta** 生成 `.d.ts`，CI 校验生成物无 diff；
2. `IPlatformServices` 新增 WebBrowser 实现：文件读写、配置持久化全部改走后端接口，浏览器不再直接访问磁盘；
3. `DocumentConverter` 下沉至 `roseui-office`，按 **B1 策略（定夺 2026-07-31）** 完成 Word/Excel/PPT 解析，**零质量折损**：
   - **docx → Markdown**：沿用上游 `pandoc`（`pandoc -f docx -t markdown`），以 **rust-embed 内嵌**方式随单二进制分发，首次运行解压至缓存目录（与二进制分离），运行期零 Node；
   - **xlsx → JSON**：沿用 `calamine`，100% Rust，零外部依赖，零折损（已具备）；
   - **ppt → JSON / 浏览器预览**：沿用 `officecli`（iOfficeAI/OfficeCli 独立预编译二进制，非 Node），同样 rust-embed 内嵌随单二进制分发，首启解压；
   - 移除前端 `mammoth` / `xlsx-republish` / `officeparser` / `pptx2json` 等死代码依赖（前端 `DocumentConverter.ts` 已确认全仓零引用，可直接删除）；
   - 代价：单二进制体积 +~50MB（pandoc + officecli），登记为可接受技术债；
   - **不再**保留"docx 经 `roseui-runtime`(Managed Node) 过渡"的兜底方案（B1 已消除质量折损，无需借道 Node）。
4. 旧 SQLite 迁移逻辑移植为 AionCore 新增 `roseui-db::legacy_handoff` 模块，支持事务备份、失败回滚、Dry-Run。

### 模块 4：AionCore 后端适配（核心）

1. **新增 `roseui-webhost` crate**，职责：
   - `rust-embed` 内嵌 React dist，**默认单二进制分发**；`--static <dir>` 仅作开发覆盖；
   - SPA 路由回退（非 `/api`、非 `/ws` 的 404 一律回 `index.html`）；
   - 静态资源 ETag / Cache-Control / gzip（tower-http `CompressionLayer`）；
   - **业务路由直接挂载**（单进程，不存在反向代理层）；
2. **CORS 与安全中间件**：严格执行前置约束第 5 条，实现为独立 `security` 模块，默认最严策略，宽松项必须显式命令行开启；
3. **数据层维持 SQLx**，不引入新 ORM。新增表沿用现有 `migrations/` 编号规则（当前已至 033）；
4. **CLI（clap）**：
   ```
   rosecore            [--port 3080] [--host 127.0.0.1] [--static <dir>] [--no-open]   # server 为默认行为，无 serve 子命令、无 --dev 标志
   rosecore migrate --from-electron <旧库路径> [--dry-run] [--backup <dir>]
   rosecore reset   [--config] [--database] [--all]
   rosecore doctor                    # 环境自检：端口、权限、数据目录、CLI agent 探测
   ```
5. **日志统一**：全局 tracing + tracing-appender，滚动归档至数据目录 `logs/`；前端日志经 `/api/log` 汇入同一体系；
6. **WebSocket 加固**：长连接超时回收、心跳保活、会话绑定、断线期间消息队列缓冲，解决浏览器标签页休眠断连导致的对话中断；
7. **首启体验（小白可用，强制要求）**：
   - 端口被占用时自动递增探测可用端口并提示；
   - 启动成功后自动调用系统默认浏览器打开（`open` crate，已在依赖中），`--no-open` 可禁用；
   - 终端输出清晰的访问地址与二维码（局域网模式）；
   - 首次运行自动初始化数据目录、生成管理员凭据并在终端明示。

### 模块 5：新增 Wiki 知识库能力（`roseui-wiki`）

> 现有 24 个 crate 无知识库能力，此为产品愿景缺口，作为**新增功能**独立立项，不受"不删减功能"条款约束。

1. 新增 `crates/roseui-wiki`，遵循既有 domain crate 结构（`lib.rs / routes.rs / service.rs / state.rs / types.rs`）；
2. 双链语法：**Obsidian 风格 `[[页面名]]`**（用户拍板，生态通用，不自定义）。
3. 一期能力（本轮交付）：
   - 文档 CRUD，Markdown 存储，落盘为本地文件（经 `roseui-file` 的 `path_safety` 沙箱，防目录穿越）
   - 全文检索（SQLite FTS5，零新增依赖）
   - 标签与 `[[页面]]` 双向链接（保存时后端抽取 link 关系入库，前端渲染时高亮跳转）
   - **四类知识来源（全部纳入一期）**：
     1. 手动创建
     2. Agent 写入：经 `roseui-mcp` 注册 builtin 工具 `wiki_read` / `wiki_write` / `wiki_search`
     3. 拖入 / 收到的文档：经 B1 的 pandoc 等管线转为 Markdown 后建页（docx→md 走内嵌 pandoc sidecar）
     4. 沉淀用户↔Agent 对话过程产生的价值内容（对话蒸馏：用户触发"沉淀到知识库"或 Agent 经 MCP 写入）
4. 二期三处实质增强（2026-07-31 已交付）：
   - **frontmatter 结构化字段**（migration `035_wiki_frontmatter_edges.sql`）：`wiki_pages` 加 `category`/`doc_type`/`source_ref`/`status`/`extra`(JSON)，解锁按行业词汇过滤检索；
   - **typed edges**（`wiki_edges` 表，受控枚举 `cites`/`supersedes`/`conflicts`/`exemplifies`/`relates`）：替代裸 title-link 做关联推理，`wiki_links`（`[[ ]]`）保留兼容；
   - **`wiki_cite` / `wiki_link_graph` MCP 工具**：精准引用（带 `wiki:<page_id>#anchor` 锚点）+ 关联网络（含 edge_type 与 direction）。
5. **检索架构红线（FTS5 与向量的关系）**：
   - **FTS5 是唯一的基础检索层，永不被移除、永不被向量检索替代。** FTS5 负责精确术语（法条编号、案号、专有名词）与结构化字段过滤（`category`/`doc_type`），具备确定性、可解释性、零依赖三项不可替代特性。
   - 向量检索（若未来引入）**仅作为语义补充**，用于"词汇不重叠但语义相关"的自然语言召回（如"和租客闹翻了"→ 租赁纠纷）；与 FTS5 是**正交的两个维度**，关系为"混合召回"而非"替代升级"。
   - **混合检索规范**：召回阶段 FTS5 与向量各自独立执行，融合阶段用 RRF/加权合并，最终结果必须回链 `chunk_id + source_doc#page` 交给 `wiki_cite`，保证可溯源。
   - **禁止**：以向量检索替换 FTS5；引入向量能力导致数据出本机（禁止调云端 embedding API）；为向量检索引入与"禁止重依赖"口径冲突的运行时（除非以 feature gate 隔离且默认关闭）。
6. 二期其余项（自动摘要、知识图谱可视化）本轮不实现，不预留空壳代码。

### 模块 6：废弃能力与降级适配

1. 移除：桌面窗口、系统托盘、应用菜单、桌宠、自动更新、Chromium GPU 参数配置；
2. 系统通知改为浏览器 Notification API（需用户授权）+ 页面内提示；弹窗对话框改为前端网页弹窗；
3. **遥测：默认完全关闭**。崩溃与错误统一落本地日志文件。Sentry 作为可选开关，需用户在设置中显式启用并自填 DSN，默认不编译进发布二进制（feature gate）。

## 三、运行模式

### 模式 A：开发调试

```bash
# 终端 1 — 后端（server 是默认行为，无 serve 子命令；--dev 非有效 flag）
cd upstream-AionCore
cargo run -- --port 3080 --host 127.0.0.1

# 终端 2 — 前端
cd upstream-AionUi
bun install
bun run dev            # Vite :5173，已配置 proxy → :3080（同源，无跨域）
```
浏览器打开 `http://localhost:5173`，支持热更新。

> 注：后端 CLI 实测命令签名（`rosecore --help`）—— 无 `serve` 子命令，
> server 为默认启动动作；无 `--dev` 标志；端口/绑定用顶层 `--port` / `--host`。
> 健康检查端点为 `GET /health`（非 `/api/health`）。

### 模式 B：成品交付（用户最终形态）

```bash
# 1. 构建前端
cd upstream-AionUi && bun install && bun run build

# 2. 前端产物同步至后端内嵌目录
cp -r packages/desktop/src/renderer/dist ../upstream-AionCore/crates/roseui-webhost/assets/

# 3. 编译单二进制
cd ../upstream-AionCore && cargo build --release

# 4. 运行（server 为默认行为，无 serve 子命令）
./target/release/rosecore --port 3080 --host 127.0.0.1
```
启动后访问 `http://127.0.0.1:3080`（需在浏览器手动打开，或加 `--no-open` 之外的自启逻辑视实现而定）。**无需安装任何桌面软件，无需附带任何目录。**

> 注：前端构建产物目录为 `packages/desktop/src/renderer/dist`（非 `packages/desktop/dist`），
> 与 `vite.config.ts` 中 `root: packages/desktop/src/renderer` 一致。
